# Linux & Docker Debugging Commands -- Detailed Guide

This document explains important Linux commands often used while working
with **servers, Docker containers, and production systems**.\
Each command includes its **purpose, significance, and real-world use
cases**.

------------------------------------------------------------------------

# 1. `ls` -- List Files and Directories

## What it does

`ls` displays the files and directories present in the current working
directory.

## Syntax

    ls

## Common Variants

    ls -l
    ls -a
    ls -lh

  Option   Meaning
  -------- ---------------------------
  `-l`     Long listing format
  `-a`     Show hidden files
  `-lh`    Human readable file sizes

## Significance

This command helps you **inspect the file structure** inside a system or
container.

## Real Use Cases

-   Verify whether application files exist inside a Docker container.
-   Check if configuration files were copied correctly.
-   Inspect log directories.

Example:

    ls /app

------------------------------------------------------------------------

# 2. `ps` -- Process Status

## What it does

`ps` shows the **currently running processes** in the system.

## Syntax

    ps

## Common Variants

    ps aux
    ps -ef

  Command    Meaning
  ---------- -----------------------------
  `ps aux`   Shows all running processes
  `ps -ef`   Full process format

## Significance

It helps identify **which programs are running and their process IDs
(PID)**.

## Real Use Cases

-   Check whether a server process is running.
-   Debug crashed applications.
-   Identify background services.

Example:

    ps aux | grep node

This shows whether a **Node.js application is running**.

------------------------------------------------------------------------

# 3. `top` -- Real-Time System Monitoring

## What it does

`top` provides a **live view of system processes and resource usage**.

## Syntax

    top

## Information Displayed

-   CPU usage
-   Memory usage
-   Running processes
-   System load

## Significance

This command is crucial for **performance monitoring**.

## Real Use Cases

-   Identify processes consuming high CPU.
-   Monitor server health.
-   Detect memory leaks.

Example scenario: If your container becomes slow, run:

    top

to check which process is consuming resources.

------------------------------------------------------------------------

# 4. `df` -- Disk Space Usage

## What it does

`df` shows the **disk usage of file systems**.

## Syntax

    df

## Common Variant

    df -h

  Option   Meaning
  -------- -----------------------
  `-h`     Human readable format

## Significance

Helps determine whether the system is **running out of storage space**.

## Real Use Cases

-   Detect disk full errors.
-   Monitor storage capacity in production servers.
-   Check available disk before deployments.

Example:

    df -h

Output shows: - Total space - Used space - Available space

------------------------------------------------------------------------

# 5. `du` -- Disk Usage of Files/Folders

## What it does

`du` measures the **space used by files or directories**.

## Syntax

    du

## Common Variants

    du -h
    du -sh *

  Option   Meaning
  -------- ----------------
  `-h`     Human readable
  `-s`     Summary
  `*`      All folders

## Significance

Helps identify **which directory is consuming storage**.

## Real Use Cases

-   Find large log files.
-   Identify large build artifacts.
-   Debug storage issues in servers.

Example:

    du -sh /var/log

------------------------------------------------------------------------

# 6. `docker logs` -- View Container Logs

## What it does

Displays logs generated by a Docker container.

## Syntax

    docker logs <container_id>

## Follow Logs in Real-Time

    docker logs -f <container_id>

## Significance

Logs are essential for **debugging applications inside containers**.

## Real Use Cases

-   Identify application errors.
-   Monitor service output.
-   Track request activity.

Example:

    docker logs my-app

------------------------------------------------------------------------

# 7. `ping` -- Network Connectivity Check

## What it does

`ping` checks whether a host is reachable over the network.

## Syntax

    ping google.com

## Significance

It verifies **network connectivity between systems**.

## Real Use Cases

-   Check internet connectivity.
-   Debug DNS resolution.
-   Test server reachability.

Example:

    ping database-server

------------------------------------------------------------------------

# 8. `curl` -- Send HTTP Requests

## What it does

`curl` is used to **send HTTP requests to servers or APIs**.

## Syntax

    curl <url>

Example:

    curl http://localhost:3000

## Significance

It is widely used for **testing APIs and web services**.

## Real Use Cases

-   Test API endpoints.
-   Check if a service is responding.
-   Debug microservices communication.

Example:

    curl -X GET http://localhost:3000/api/users

------------------------------------------------------------------------

# 9. `docker exec` -- Execute Commands Inside Containers

## What it does

Runs commands inside a running Docker container.

## Syntax

    docker exec -it <container_id> /bin/sh

  Option   Meaning
  -------- -------------
  `-i`     Interactive
  `-t`     Terminal

## Significance

Allows developers to **inspect and debug containers directly**.

## Real Use Cases

-   Enter container shell
-   Check logs and files
-   Run debugging commands

Example:

    docker exec -it my-container /bin/sh

------------------------------------------------------------------------
